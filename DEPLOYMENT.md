# Public deployment — Render Blueprint

This project is packaged to run behind a public HTTPS web-service URL. The included `render.yaml` provisions one Docker web service and a persistent disk for SQLite state. The application serves both the React frontend and FastAPI backend from the same origin. **This blueprint uses a paid Render web-service plan plus a paid persistent disk**; Render does not preserve data on the default ephemeral filesystem. The selected 0.5 CPU / 512 MB compute plan is currently listed at $7/month, with disk storage billed separately; confirm current pricing before applying the Blueprint.

## Before you start

- A GitHub or GitLab repository containing this project.
- A Render account with permission to create a paid web service and persistent disk (the Blueprint requests the `0.5c-512mb` plan and a 1 GB disk; plan availability/pricing can change).
- A unique administrator email/name/password and a separate high-entropy telemetry ingestion secret.

## Steps

1. Create a **private** GitHub repository (recommended) and upload the contents of this project. Keep `.env`, database files, runtime exports and all real credentials out of Git. The checked-in evidence is synthetic participant material.
2. In Render, choose **New → Blueprint** and connect the repository containing `render.yaml`.
3. Review the Blueprint before applying it. It creates the web service `variant404-security-assurance`, sets `/api/health` as the health check, configures `DATA_DIR=/var/data`, and attaches a persistent disk at `/var/data`.
4. Enter the values for `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_NAME`, `INITIAL_ADMIN_PASSWORD` and `INGEST_SECRET` in the Render environment-variable prompt. Use a unique password of at least 12 characters and a different random ingestion secret (32+ characters recommended). `APP_SECRET` is generated by the Blueprint. Do not put secrets in the repository or paste them into a public issue.
5. Apply the Blueprint and wait for the Render build/deploy to report **Live**. The Docker build compiles the React frontend and packages the FastAPI backend.
6. Open the public HTTPS URL shown on the Render service page. Sign in with the bootstrap admin account, change the password if required by your policy, then use **Workspace access** to create individual team accounts. Never share the bootstrap account.
7. In **API Monitor → Ingestion setup**, copy the ingestion endpoint. Configure an authorized gateway/log forwarder to send only metadata using the `X-Ingest-Key` secret stored in that forwarder's secret manager. Test with a non-sensitive test event and confirm it appears in Recent events.
8. Set up a backup policy for the persistent disk and document who owns account provisioning, approvals, incident triage and restoration testing.

## Updates

Push changes to the connected repository. Render will build and deploy the new commit. Back up the persistent SQLite files before major schema changes. The service currently runs one process/instance and uses SQLite with a disk mounted to that service.

## Important hosting constraints

- A Render persistent disk can be attached to only one service instance; this Blueprint explicitly sets `numInstances: 1`. This is a practical demo / small-team deployment, not a multi-instance HA design.
- To scale horizontally or run more than one application instance, migrate SQLite state and authentication to managed PostgreSQL and introduce shared session / rate-limit storage before increasing instance count.
- The web service is internet-accessible once deployed. Protect it with unique credentials, admin/approver role discipline, security updates, backups and controlled account provisioning.
- Do not point it at any real organization or service unless you have written authorization and have completed a separate security review. The current remediation modules operate on simulation state only.

## Alternative: any Docker host

The image exposes port `10000`. A host with Docker and persistent-volume support can run it with the same environment variables. Mount a durable writable volume at `/var/data`, set `ENVIRONMENT=production`, `DATA_DIR=/var/data`, `COOKIE_SECURE=true`, `APP_SECRET`, `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_NAME`, `INITIAL_ADMIN_PASSWORD` and `INGEST_SECRET`, and terminate HTTPS at a trusted reverse proxy. Never expose the app over plain HTTP on a public network.
